# Attack the Premise

When two or more fixes have failed for the same symptom, stop fixing. The
fixes shared a premise. Question that instead.

**Why:** repeated failure at the same layer is evidence the problem lives at
a different layer. Each new fix on a wrong premise adds code that future
readers must un-learn.

**The pattern:**

- Take a census of the failed attempts and name the assumption they shared.
- Ask which actor actually holds the imbalance, not which one reports it.
- State the premise you are attacking before proposing the new fix, so the
  next person can tell the difference between a new idea and a fourth attempt
  at the old one.
